# 交互设计整改清单（2026-10-18）

## 一、盘点范围与方法

覆盖 `src/renderer/src` 全部 42 个源码文件（10 个 views + 15 个 components + 8 个 composables + 工具/入口），以两轮自动化静态扫描 + 人工逐点复核完成盘点：

- 扫描 1：全部 `async` 函数中 `await window.api.*` 但**无 try/catch 异常保护**的节点（173 处 API 调用全量过筛）
- 扫描 2：`await window.api.*` 但**完全无用户反馈**（无 toast/确认框）的操作节点
- 人工复核：全部删除/重置/清空类破坏性操作（22 处）、全部确认弹窗（12 处）、全部文件导入对话框（6 处）、空状态/加载态/防连点覆盖情况

**盘点结论**：项目此前已经过多轮 UX 治理，大部分核心路径（分镜删除/渲染、场景板/角色/道具删除、预设删除、批量操作等）已具备「确认 + 节流 + loading + 成功/失败 toast」完整闭环。本次整改聚焦于残余的 4 类不一致问题，共修复 **21 个交互节点**。

## 二、统一交互规范（本次确立并落地）

| 规范 | 实现位置 |
|---|---|
| 危险操作（删除/清空/重置/停止）一律 `confirmDanger`（红色确认钮，ESC/遮罩=取消） | `src/renderer/src/utils/confirm.ts` |
| 普通确认（复制/批量/覆盖）一律 `confirmAction` | 同上 |
| 快速重复点击一律 `throttleTap` 或 `:loading`/`disabled` 防重入 | `src/renderer/src/utils/throttle.ts` |
| 任何失败不得静默：调用点 try/catch 给错误 toast；漏网异常由全局兜底捕获提示 | `src/renderer/src/main.ts`（新增兜底） |
| 主进程文件对话框取消哨兵 `'User cancelled'`：渲染进程静默，不弹「导入失败」 | 各导入调用点 |
| Toast 时长：success/info 2s、warning 2.5s、error 3.5s（既有规范，保持不变） | `src/renderer/src/main.ts` |
