> 对应审计项 **P1-04（Windows 代码签名）** 与 **P1-06（三平台 CI/打包实跑）**。
> 仓库内已完成的配置：`electron-builder.yml` 的 `win.signtoolOptions.signingHashAlgorithms: [sha256]`、

## 一、Windows 代码签名（P1-04）

### 1. 证书准备

| 类型 | 适用 | 说明 |
|---|---|---|
| OV 代码签名证书 | 常规分发 | 便宜，但 SmartScreen 信誉需累积下载量后才消失 |
| EV 代码签名证书 | 立即消除 SmartScreen | 需硬件令牌/USB Key，CI 需云签名或自托管 runner |
| Azure Trusted Signing | 无硬件令牌的现代方案 | 按次计费，支持 CI 托管签名（推荐评估） |

> 无证书时 `electron-builder` 会跳过签名，产物可用，但 Windows 11 首次运行会显示「未知发布者」。

### 2. 注入 CI secrets

在 GitHub 仓库 `Settings → Secrets and variables → Actions` 增加：

| Secret | 内容 |
|---|---|
| `CSC_LINK` | `.pfx` 文件的 base64（`base64 -w0 cert.pfx`）或可访问的绝对路径 |
| `CSC_KEY_PASSWORD` | pfx 口令 |

`electron-builder` 会自动读取这两个环境变量完成签名，无需额外脚本。仓库内**不存证书**。

若使用 EV 硬件令牌：GitHub 托管 runner 无法直连 USB 令牌，需：

1. 自托管 Windows runner（令牌插在本机），或
2. 使用 Azure Trusted Signing / 云签名服务的 `signtool` 包装脚本。

### 3. 本地签名验证

```powershell
# 1) 注入后打包
$env:CSC_LINK="C:\path\cert.pfx"; $env:CSC_KEY_PASSWORD="***"
npm run build:win

# 2) 验证签名
Get-AuthenticodeSignature .\release\本地AI短剧工坊-1.0.0-setup.exe | Format-List Status,SignerCertificate

# 期望：Status = Valid；若为 NotSigned 说明 secrets 未注入成功
```

### 4. SmartScreen 复测

1. 把签名包上传到可公网下载的位置（或使用未下载过的测试机）；
2. 全新 Windows 11 环境下载并运行；
3. 期望不再出现「Windows 已保护你的电脑」；
4. 若仍提示，确认签名时间戳（`signtoolOptions` 默认带时间戳）与证书链完整。

## 二、三平台 CI 实跑（P1-06）

### 1. 日常 verify（push / PR）

`.github/workflows/ci.yml` 已在 `ubuntu / windows / macos` 三平台执行：

```
npm ci → npm run lint → npm run typecheck → npm test（ubuntu 上为 test:coverage）→ npm run build
```

首次实跑步骤：

```bash
git push origin <branch>        # 触发 verify
gh run watch                    # 或网页 Actions 页观察
```

关注点：

- Windows/macOS runner 上 `onnxruntime-node`、`ffmpeg-static` 是否按平台正确安装；
- `postinstall` 的 `patch-element-plus.mjs` 是否在 CI 正常执行；
- coverage 阈值（lines/functions/branches 60%）是否在 ubuntu 通过。

### 2. 打包实跑（tag）

```bash
git tag v1.0.0-rc1
git push origin v1.0.0-rc1       # 仅 tag 触发 package job
```

| Runner | 产物 | 验收 |
|---|---|---|
| windows-latest | NSIS `.exe` | 安装 → 启动 → 项目列表可见 → ComfyUI 自检可跑 |
| macos-latest | `.dmg` / `.zip` | 打开（首次需 `right-click → Open`，未公证时）；主进程无崩溃 |
| ubuntu-latest | `.AppImage` / `.deb` | 安装启动；ffmpeg 可执行 |

> 原生二进制（ffmpeg-static / onnxruntime-node）不能跨平台打包，**必须在对应平台打**，这也是 matrix 的原因。

### 3. macOS 公证（可选，需 Apple 开发者账号）

`electron-builder.yml` 的 `mac` 段未配置 `notarize`。如需消除 Gatekeeper 提示：

```yaml
mac:
  notarize:
    teamId: "<TEAM_ID>"
```

并配置 secrets：`APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID`。
无账号时保持现状，在文档/下载页注明「首次打开需右键打开」。

## 三、失败排查清单

| 症状 | 可能原因 | 处理 |
|---|---|---|
| Windows 产物未签名 | `CSC_LINK` 未注入/口令错 | 查看 CI 日志中 electron-builder `signing` 段 |
| mac 打包报 `ffmpeg-static` 缺二进制 | 依赖安装平台不符 | 确认在 macos runner 上 `npm ci` |
| Linux AppImage 启动缺 lib | runner 基础镜像缺库 | 文档注明依赖，或改用 `deb` |
| verify 在 mac 上 typecheck 失败 | 路径大小写敏感差异 | 修正 import 大小写（Linux/mac 区分大小写） |
| nightly 启动计时为空 | runner 无图形环境 | 夜间任务固定 `windows-latest`（已配置） |
