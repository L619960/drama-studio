## 一、项目现状

Drama Studio 是一个基于 ComfyUI 的 AI 短剧自动生成流水线，覆盖：剧本解析 → 角色定妆 → 道具图 → 场景板 → 分镜首帧 → 图生视频 → 合成字幕 BGM → 成片。

当前已跑通全流程，核心图片生成质量已达标（纯灰棚拍定妆、场景无湿地面/壁灯、首帧服装一致）。但仍有交互引导、工程健壮性、图片一致性三个类别的待补全项。

## 三、待补全需求（按优先级）

### P0 — 影响用户核心流程

#### P0-1. 分镜审核门禁与"一口气跑到底"联动
**现状**：开拍对话框有"一口气跑到底"开关（gateStages=[]），但分镜审核门禁（shotReviewGate）是全局设置，不随开关变化。开关打开后仍会停在分镜审核。  
**需求**：
- "一口气跑到底"开关同时把 shotReviewGate 临时设为 off（本项目生命周期内）
- 关闭开关时恢复用户全局设置
- 在导演控制台常驻显示当前门禁状态（"分镜审核：开/关"）

**验收**：打开开关 → 新剧全程不停顿直到达成；关闭开关 → 分镜审核门禁正常拦截。

#### P0-2. 导演对话"继续"指令覆盖率
**现状**：resume_director 工具已内置，但 LLM 有时只是文字回复"我查一下状态"而不调用工具。  
**需求**：
- 导演系统提示词（system prompt）里强化：用户说"继续/开始/接着跑/没问题"时**必须**调用 resume_director，禁止纯文字回复
- 加 fallback：LLM 回复包含"继续"且当前 paused 状态时，自动触发 resume
- 对话日志里区分"已触发 resume"和"仅文字回复"

**验收**：paused 状态下说"继续"→ 流水线立即恢复，不再只是聊天。

#### P0-3. 应用重启后残留任务恢复
**现状**：应用重启后 director-state.json 显示 running=true，但实际 ComfyUI 队列已空，流水线挂死。  
**需求**：
- 应用启动时检测 director-state.json：running=true 但超过 10 分钟无新日志 → 标 error，提示"上次任务中断，可从失败阶段重跑"
- 不要静默保留 running 状态让用户以为还在跑
- 提供"从上次失败阶段继续"一键入口

**验收**：杀进程后重启应用 → 看到清晰的"任务中断"提示和"继续"按钮，不是卡死。

### P1 — 图片质量与一致性

#### P1-1. 首帧-定妆照自动相似度比对
**现状**：首帧靠 i2i 参考图锁脸，但服装细节偶尔漂移（如苏晴首帧背景多一个推门的苏晴）。  
**需求**：
- 首帧生成后，自动做人脸相似度比对（用现有人脸检测模型）
- 服装关键词匹配：定妆照 lookEn 里的服装词 vs 首帧 promptEn 里的服装词
- 低于阈值（人脸相似度 < 0.7 或服装关键词缺失）自动重抽 1 次
- 重抽仍失败则标 warn，不阻塞流程
- 日志记录每次比对分数

**验收**：单人镜不会出现两个人；服装配饰与定妆照一致。

#### P1-2. 场景图跨镜一致性
**现状**：同一场景在不同分镜里生成的全景图细节不一致（窗位置、桌椅数量）。  
**需求**：
- 同一场景名复用第一次生成的场景全景图（缓存），不重复生成
- 后续分镜的场景板基于已缓存的全景图做局部修改，而非重新 t2i
- 场景名标准化：避免"公司会议室"vs"会议室"被识别成两个场景

**验收**：同一部剧里同一场景的所有分镜背景一致。

#### P1-3. 角色跨帧一致性强化
**现状**：首帧 i2i 融合路径（qwen2511_i2i_edit）有时会漂移五官。  
**需求**：
- i2i 融合时参考图权重（denoise strength）可调，默认 0.55
- 多角色同框时，每个角色的定妆照都作为参考图传入
- 加 face restore 后处理（CodeFormer/GPEN）

**验收**：同角色在不同分镜里五官一致，不换脸。

#### P1-4. 负面词库统一管理
**现状**：负面词分散在 negatives.ts、imagePrompts.ts、各阶段 builder 里，容易漏。  
**需求**：
- 所有 t2i 阶段统一通过 negatives.ts 组装负面词
- 按阶段分类：casting（棚拍）/ scene（外景噪声）/ shot（人群/OOC）/ prop
- 每个阶段的负面词在 settings.json 里可覆盖
- 删除旧代码里散落的硬编码负面词

**验收**：改一处负面词，所有阶段生效；不再出现"某阶段忘加负面词"的问题。

### P2 — 工程健壮性

#### P2-1. ComfyUI 连接失败重试与降级
**现状**：ComfyUI 没启动时直接报错，没有友好提示。  
**需求**：
- 启动时检测 ComfyUI /system_stats，失败时弹引导："ComfyUI 未启动，请先启动 D:\ComfyUI-V20"
- 提供"一键启动 ComfyUI"按钮（调 start-process）
- 生成中途 ComfyUI 断开 → 标 error，不卡死

**验收**：ComfyUI 没开时点开始任务 → 看到清晰引导，不是 unhandled error。

#### P2-2. 生成失败自动重抽
**现状**：单张图生成失败直接标 error，需要手动重试。  
**需求**：
- t2i 失败自动重试 2 次（间隔 5 秒）
- i2v 失败自动重试 1 次
- 重试仍失败才标 error，记录错误原因
- 区分 transient error（显存不足/超时）和 permanent error（模型缺失/prompt 错误）

**验收**：网络抖动或偶发 OOM 不导致整剧失败。

#### P2-3. 磁盘空间与产物清理
**现状**：每集生成大量中间图，磁盘慢慢占满。  
**需求**：
- 生成前检查磁盘剩余空间（< 5GB 警告）
- 项目删除时清理对应文件夹
- 提供"清理临时产物"按钮（保留最终成片，删除中间帧）
- 日志文件按大小轮转

**验收**：跑 10 集后磁盘不爆；清理按钮能回收空间。

#### P2-4. 日志分级与查看
**现状**：所有日志混在一起，warn 刷屏影响剧情判断。  
**需求**：
- 导演控制台日志面板按级别过滤（info/success/warn/error）
- warn 默认折叠，只显示 error 和关键 info
- 点某条日志能看到完整 prompt/响应
- 日志导出（按项目导出 txt）

**验收**：跑一部剧，日志面板不超过 50 条可见；error 一眼可见。

### P3 — 体验优化

#### P3-1. 导演控制台常驻状态条
**现状**：当前阶段、进度、剩余时间散落在各处。  
**需求**：
- 顶部常驻状态条：当前阶段 + 进度百分比 + 已完成/总数镜头 + 预计剩余时间
- paused 时红色高亮"任务暂停在 XX，点击继续"
- 鼠标悬停看详细阶段列表

**验收**：打开控制台一眼看到进度，不用翻日志。

#### P3-2. 分镜审核面板优化
**现状**：逐镜确认首帧需要点很多次。  
**需求**：
- 分镜审核面板支持"全部通过"按钮
- 每镜显示：首帧图 + prompt 摘要 + "通过/重出"按钮
- 重出时可调 seed 或微调 prompt
- 支持键盘快捷键（→ 下镜，Enter 通过）

**验收**：3 分钟审完 10 镜。

#### P3-3. 导演对话快捷指令
**现状**：导演对话支持自然语言，但常用操作要打字。  
**需求**：
- 输入框上方加快捷按钮：[继续] [暂停] [重渲第X镜] [看进度]
- 点按钮直接发对应指令，不用打字
- 支持 @镜头号 引用具体分镜

**验收**：常用操作一键完成。

#### P3-4. 项目列表搜索与排序
**现状**：项目多了找不到。  
**需求**：
- 项目列表加搜索框（按标题/剧本关键词）
- 按创建时间/完成状态/片名排序
- 显示每个项目的缩略图（首帧）

**验收**：20 个项目时 5 秒找到目标。

## 四、技术债

### 4.1 模型工作流硬编码
- 当前 klein_t2i_clean / qwen_t2i_hq / qwen2511_i2i_edit 等工作流名硬编码在 builder 里
- 应该抽到 settings.json，用户可在设置里改默认工作流
- 每个阶段（casting/scene/shot/prop）可独立选模型

### 4.2 状态机与 UI 不同步
- director-state.json 更新后，UI 有时不刷新
- 应该用事件驱动（IPC push）而非轮询

### 4.3 测试覆盖
- 目前只有端到端手动验证，没有单元测试
- 关键模块（negatives 组装、prompt 生成、状态机）应有单测

### 4.4 错误处理
- 很多 catch (e) 只是 console.log，没有结构化错误码
- 应该统一错误分类（transient/permanent/user/config）

- [ ] ComfyUI 断开有友好提示

## 六、建议开发顺序

1. **P0-1 + P0-3**（门禁联动 + 重启恢复）— 解决用户最容易卡住的两个点
2. **P1-1 + P1-2**（首帧比对 + 场景一致性）— 提升图片质量
3. **P2-1 + P2-2**（ComfyUI 引导 + 自动重抽）— 工程健壮性
4. **P3-1 + P3-2**（状态条 + 审核面板）— 体验优化
5. **P1-3 + P1-4**（跨帧一致性 + 负面词统一）— 深度打磨
6. 技术债逐步还
